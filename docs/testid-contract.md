# COS2 `data-testid` Contract

**Audience:** COS2 development team
**Owner:** David Dahan, QA
**Status:** Proposed — please review and confirm before the first UI sprint closes

---

## Why this document exists

Automated tests need stable handles on UI elements. There are three ways to get them:

1. **CSS classes** — generated by the component library, change on every upgrade. Brittle.
2. **Text content** — breaks the moment a label is reworded or the app is localised. Brittle.
3. **`data-testid` attributes** — explicit, stable, invisible to users, costs nothing at runtime.

Only the third works. Adding these attributes while the components are being written costs roughly zero. Retrofitting them after the fact, against a suite of already-brittle tests, costs weeks.

**The ask:** add the attributes below as each screen is built. `mock/server.js` in the QA repo is a working reference implementation of every one of them.

## Four requests beyond the attributes

**1. Key routes by SEID, never SSN.**
`/educator/1000000001`, not `/educator/900112222`. An SSN in a URL is written to browser history, proxy logs, server access logs and `Referer` headers — masking the SSN on screen while putting it in the address bar accomplishes nothing. The same applies to DOM attributes: `data-seid`, never `data-ssn`.

**2. Omit restricted elements, do not disable them.**
For a district user the birth date element should not exist in the DOM. A hidden or disabled element is still readable via View Source, and the QA suite asserts absence, not invisibility.

**3. Enforce permissions server-side as well as in the UI.**
`SEC-016` POSTs directly to a save endpoint as a district user and requires a `403`. Hiding a button is a usability choice; refusing the request is the actual control.

**4. Provide a non-prod data reset endpoint or script.**
Tests that create records need to clean up, or the QA database drifts and the suite goes flaky within a fortnight. A `POST /test/reset` guarded to non-prod, or an approved SQL teardown script, solves this permanently.
